# CareerMate P2 — CV and AI Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:executing-plans. Steps use checkbox (`- [ ]`) syntax.

**Goal:** A candidate uploads a real CV, and the AI features answer from a real model — still answering when any single free tier is exhausted.

**Architecture:** Unchanged layering. Two new subsystems: `src/lib/ai/` (provider adapters behind one router) and Supabase Storage behind `src/lib/supabase/storage.ts`. Match scores are computed in code, not by a model, so they are stable and explainable; the model only narrates the evidence.

**Spec:** [`docs/superpowers/specs/2026-09-23-careermate-rebuild-design.md`](../specs/2026-09-23-careermate-rebuild-design.md) §3.5, §3.6, §3.7

## Global Constraints

- **Every server action's service re-checks role and ownership**, ownership predicate in the `where`. Same rule P0 and P1 were written around.
- **A feature never names a provider.** It asks the router for a completion. Only `src/lib/ai/providers/` knows Gemini or Groq exists.
- **A provider is available only when its key is present.** No key means the deployment simply has fewer providers, never a crash.
- **The chain always answers.** `mock` is last, always configured, deterministic. A response it produced is labelled a fallback in the UI, never passed off as model output.
- **Model output is never trusted as HTML.** It renders as React children; anything needing structure is parsed through a Zod schema first, and a response that fails to parse is a retryable failure.
- **AI never invents credentials.** Prompts are given the candidate's own facts and instructed to work only from them. This is the spec's stated rule and the product's whole claim.
- CV files go to a **private** bucket. Downloads are short-lived signed URLs minted after an authorization check — a candidate their own, an employer only CVs attached to an application to one of their own jobs.
- New migrations are committed and any new table gets deny-all RLS (`tests/unit/rls-migration.test.ts` enforces it across every migration).

## Review Focus

1. **Every provider key absent.** Expected: the feature still answers, from `mock`, visibly labelled — not a 500, not an empty panel. → Task 2.
2. **First provider returns 429 mid-chain.** Expected: the next provider serves it, the attempt is recorded, and that provider is skipped for a cooldown rather than retried on every later request. → Task 2.
3. **A provider returns prose where JSON was required.** Expected: treated as a retryable failure and failed over, not rendered as a broken panel or stored as garbage. → Task 2.
4. **An employer requesting a signed URL for a CV attached to another company's application.** Expected: refused, no URL minted. → Task 4.
5. **A 12MB file, or a .exe renamed .pdf.** Expected: rejected server-side by size and by sniffed content type, not only by the browser. → Task 3.

## Task 1: Provider contract and the mock

**Files:** Create `src/lib/ai/types.ts`, `src/lib/ai/providers/mock.ts`, `src/lib/ai/prompts/index.ts`; Test `tests/unit/ai-mock.test.ts`

**Produces:**
- `type AiMessage = { role: 'system' | 'user'; content: string }`
- `type AiRequest = { feature: string; messages: AiMessage[]; json?: boolean; maxTokens?: number }`
- `type AiResponse = { text: string; providerId: string; promptTokens?: number; completionTokens?: number }`
- `type AiFailure = { providerId: string; reason: 'rate_limited' | 'quota' | 'server' | 'timeout' | 'network' | 'malformed' | 'refused' | 'not_configured'; message: string; retryable: boolean }`
- `interface AiProvider { id: string; label: string; isConfigured(): boolean; complete(req: AiRequest): Promise<AiResponse> }`
- `mockProvider` — always configured; deterministic per feature; returns schema-valid JSON when `json` is set.

- [ ] Write the failing test: mock is always configured; the same request twice gives the same text; a `json: true` request returns parseable JSON; it answers for every feature id the app uses.
- [ ] RED → implement → GREEN → commit.

## Task 3: Resume upload and extraction

**Files:** Create `src/lib/supabase/storage.ts`, `src/lib/resume/extract.ts`, `src/lib/db/repositories/resume.repository.ts` (extend), `src/server/services/resume.service.ts`, `src/app/(candidate)/resume/actions.ts`, `src/components/resume/*`; Modify `src/app/(candidate)/resume/page.tsx`; Test `tests/unit/resume-extract.test.ts`, `tests/services/resume.service.test.ts`

**Produces:**
- `uploadResume(user, file): Promise<Result<{ resumeId: string }>>` — validates type and size **server-side**, writes to `resumes/{profileId}/{resumeId}/{name}`, extracts text, stores the row.
- `setPrimaryResume(user, resumeId)`, `deleteResume(user, resumeId)`, `renameResume(user, resumeId, label)`
- `extractText(buffer, mimeType): Promise<string>` — `unpdf` for PDF, `mammoth` for DOCX; returns `''` on failure rather than throwing.
- `sniffMimeType(buffer): string | null` — magic bytes, so a renamed `.exe` is caught.

- [ ] Write the failing tests — **Review Focus 5**: over-size rejected server-side; a PDF magic-byte check rejects a file whose extension lies; extraction failure yields an empty string and the upload still succeeds; only the owner may set primary/delete/rename; setting a new primary clears the old one in one transaction.
- [ ] RED → implement → GREEN → commit.
